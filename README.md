# 🍽 LUMIÈRE — сайт ресторана с бронированием столиков

Fullstack портфолио-проект: современный адаптивный сайт ресторана авторской кухни с онлайн-бронированием, галереей, отзывами и панелью администратора. Данные хранятся в SQLite — бронирования и отзывы сохраняются навсегда, даже после перезапуска сервера.

![Node.js](https://img.shields.io/badge/Node.js-24-green) ![Express](https://img.shields.io/badge/Express-4-black) ![SQLite](https://img.shields.io/badge/SQLite-node%3Asqlite-blue)

## ✨ Что умеет сайт

| Раздел | Возможности |
|--------|-------------|
| **Главная** | Анимированный hero-экран, статистика, плавный скролл, фиксированная шапка с эффектом блюра |
| **О ресторане** | Фото интерьера, ключевые факты о заведении |
| **Меню** | Загружается из БД, фильтрация по категориям (закуски, салаты, горячее, десерты, напитки) |
| **Бронирование** | Форма заявки с валидацией на клиенте **и** сервере, номер заявки, минимальная дата — сегодня |
| **Галерея** | 8 реальных фотографий, лайтбокс (стрелки ←/→, Escape, клик по фону) |
| **Отзывы** | Карточки со звёздами + форма добавления, отзывы пишутся в БД |
| **Акции** | Карточки акций из БД |
| **Контакты** | Адрес, часы работы, интерактивная карта OpenStreetMap |
| **Админ-панель** | Таблица всех бронирований, статистика, фильтры, подтверждение/отмена/удаление |

## 🛠 Технологии

- **Backend:** Node.js 24, Express 4
- **База данных:** SQLite через встроенный модуль [`node:sqlite`](https://nodejs.org/api/sqlite.html) — ноль нативных зависимостей, ничего компилировать не нужно (требуется Node ≥ 22.5)
- **Frontend:** HTML5 + CSS3 (Grid, Flexbox, Custom Properties, анимации) и Vanilla JS (Fetch API, IntersectionObserver) — без фреймворков и сборщиков
- **Изображения:** JPEG (Unsplash), лежат локально в репозитории

## 🚀 Быстрый старт

```bash
git clone https://github.com/ВАШ_ЛОГИН/restaurant-website.git
cd restaurant-website
npm install
npm start          # или: node server.js
```

- Сайт: **http://localhost:3000**
- Панель бронирований: **http://localhost:3000/admin.html**

При первом запуске БД создаётся и заполняется демо-данными автоматически (файл `db/restaurant.db`: 16 позиций меню, 4 отзыва, 3 акции). Режим разработки с автоперезапуском: `npm run dev`.

## 📁 Структура проекта — что за что отвечает

```
websiterest/
├── server.js              # Express-сервер: раздача статики и весь REST API
├── db/
│   └── database.js        # Подключение к SQLite, создание таблиц, демо-данные
├── public/                # Всё, что отдаётся браузеру
│   ├── index.html         # Главная страница (все разделы сайта)
│   ├── admin.html         # Панель администратора (бронирования)
│   ├── css/
│   │   ├── style.css      # Все стили сайта: тема, сетки, анимации, адаптив
│   │   └── admin.css      # Стили панели: таблица, бейджи статусов, карточки статистики
│   ├── js/
│   │   ├── main.js        # Логика сайта: меню, акции, отзывы, бронь, лайтбокс
│   │   └── admin.js       # Логика панели: загрузка/фильтрация/изменение броней
│   └── img/
│       └── gallery/       # Фотографии блюд и интерьеров
└── package.json
```

**Ключевые части по смыслу:**

- `db/database.js` — единственное место, где живёт схема данных. Таблицы создаются через `CREATE TABLE IF NOT EXISTS`, поэтому ничего «мигрировать» не нужно: запустили — база готова. Демо-данные добавляются только если таблицы пусты, так что ваши реальные брони и отзывы не затираются.
- `server.js` — «толстый» API-слой: приём и валидация заявок, изменение статусов, CRUD отзывов. Никакой бизнес-логики на клиенте.
- `public/js/main.js` — рендерит меню/отзывы/акции из API, отправляет формы, управляет лайтбоксом и мобильным меню. Все данные из API экранируются (`escapeHtml`) — защита от XSS.
- `public/js/admin.js` — получение бронирований, фильтр по статусу, живые часы, действия «подтвердить / отменить / удалить» с подтверждением.

## 🗄 Схема базы данных

**`bookings`** — бронирования столиков

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | Номер заявки (автоинкремент) |
| `name`, `phone` | TEXT | Имя гостя и телефон |
| `guests` | INTEGER | Количество гостей (1–20) |
| `date`, `time` | TEXT | Дата (ГГГГ-ММ-ДД) и время (ЧЧ:ММ) |
| `comment` | TEXT | Пожелания (столик у окна, торт…) |
| `status` | TEXT | `новая` → `подтверждена` / `отменена` |
| `created_at` | TEXT | Когда создана заявка |

**`menu_items`** — блюда (категория, название, описание, цена, вес) · **`reviews`** — отзывы (имя, рейтинг 1–5, текст, дата) · **`promos`** — акции (бейдж, заголовок, описание)

## 📡 REST API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/menu` | Всё меню |
| GET | `/api/promos` | Акции |
| GET | `/api/reviews` | Отзывы (новые сверху) |
| POST | `/api/reviews` | Добавить отзыв `{name, rating, text}` |
| GET | `/api/bookings` | Все бронирования |
| POST | `/api/bookings` | Создать бронирование `{name, phone, guests, date, time, comment}` |
| PATCH | `/api/bookings/:id` | Сменить статус `{status}` |
| DELETE | `/api/bookings/:id` | Удалить бронирование |

Сервер валидирует: имя от 2 символов, телефон по маске, гостей 1–20, дату не в прошлом, время в формате ЧЧ:ММ, рейтинг 1–5. Ошибки возвращаются в формате `{ "error": "текст ошибки" }` с кодом 400/404.

## 🧩 Особенности реализации

- **Валидация в двух слоях:** HTML5-атрибуты и `novalidate`-скрипты на клиенте + строгие проверки на сервере. Нельзя обойти, отправив запрос напрямую.
- **Персистентность:** SQLite (WAL-режим) хранит всё в файле `db/restaurant.db`. Брони и отзывы переживают перезапуск и перезагрузку машины.
- **Идемпотентная инициализация:** `CREATE TABLE IF NOT EXISTS` + сидинг только пустых таблиц — база безопасно пересоздаётся, но не теряет данные.
- **Защита от XSS:** весь пользовательский контент (имена, отзывы, комментарии) экранируется перед вставкой в DOM.
- **Ноль сборки:** никаких webpack/vite — открыл `npm start` и работаешь. `node:sqlite` встроен в Node, единственная зависимость — Express.
- **UX-детали:** лайтбокс с клавиатурной навигацией, анимации появления через IntersectionObserver, `date.min` = сегодня в форме брони, состояние кнопок на время запроса.

## 🎨 Кастомизация

- **Заменить фото:** положите свой файл с тем же именем в `public/img/gallery/` — код менять не нужно.
- **Изменить меню/акции/отзывы-демо:** редактируйте сид-данные в `db/database.js` (или прямо в `db/restaurant.db`).
- **Перекрасить тему:** все цвета в CSS-переменных `:root` в начале `public/css/style.css` (`--gold`, `--bg` и т.д.).
- **Порт или порт из окружения:** `PORT=8080 npm start`.

## ☁️ Деплой

Проект деплоится куда угодно, где есть Node.js ≥ 22.5:

- **Render / Railway / Fly.io** — указать `npm start`, добавить persistent disk для `db/` (иначе SQLite-файл не переживёт рестарт контейнера).
- **VPS (nginx + pm2):**
  ```bash
  pm2 start server.js --name lumiere
  ```
  и проксировать `proxy_pass http://localhost:3000;` в nginx.
- На бесплатных планах без диска SQLite подойдёт для демо, но данные будут сбрасываться при рестарте — для продакшена логично переехать на PostgreSQL (слой запросов в `server.js` изолирован, замена несложная).
